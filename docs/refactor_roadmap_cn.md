# 后续分阶段重构路线图

本文档用于约束交付后的大范围重构节奏。目标是在保持当前单任务演示链路可用的前提下，逐步把上传、训练、预览、下载整理成更稳定的产品流程。

## 总体原则

- 每个阶段单独提交，避免一次性混入前端、后端和训练流程的大改动。
- 每个阶段完成后必须保留当前单任务流程可运行：采集、上传、Spann3R、3DGaussian、Viewer、点云下载。
- 训练输出、点云、截图、权重和临时文件不进入 GitHub。
- 私有 SSH 密码、AutoDL token、微信小程序密钥不写入文档或代码。

## 阶段 1：任务模型重构

统一后端任务状态，把上传检测、Spann3R 重建、3DGaussian 训练、导出、下载抽象成同一个任务对象。

验收标准：

- `/api/progress` 能稳定返回当前任务阶段、进度、loss、错误信息和 scene 名称。
- 前端状态页只消费统一字段，不再散落判断多个临时状态。
- 停止训练、导出点云、刷新状态都能明确反馈成功或失败原因。

## 阶段 2：保存策略重构

把上传图片、归档图片、训练场景、导出点云、临时缓存分层管理，减少系统盘堆积。

验收标准：

- 重启时可配置 `archive`、`delete`、`keep` 三种上传图片处理策略。
- 队列任务目录也纳入重启清理策略，可单独配置归档目录和保留数量。
- 每个 scene/job 的输入和输出互相隔离。
- 自动清理策略只处理明确的临时目录，不误删权重、代码和已确认保留的结果。

## 阶段 3：多任务能力

在单卡资源约束下先实现任务队列，再扩展到任务列表和取消操作。默认仍只并行一个 GPU 训练任务，避免抢占显存。

验收标准：

- 新上传任务进入队列，不覆盖正在训练的 scene。
- 前端能看到任务列表、当前任务、排队任务和已完成任务。
- 每个任务的下载文件按 scene/job 隔离。

## 阶段 4：前端交付优化

围绕普通用户使用流程收敛页面信息，把调试信息留在预览页和后端管理台。

验收标准：

- 首页只展示采集状态、双重关键帧筛选、有效帧统计和短按钮文案。
- 状态页纵向展示后端阶段、Viewer 链接、刷新按钮、Gaussian 进度/loss、管理动作、最新日志和点云下载列表。
- 点云下载项显示时间、大小、场景、类型，并提供复制链接。

## 阶段 5：发布硬化

补充演示前检查脚本、常见故障文档和端到端 smoke check。

验收标准：

- 一条命令完成后端语法检查、前端 JS 语法检查、关键文档敏感信息扫描。
- 文档覆盖启动、停止、重启、上传、训练、Viewer、下载和清理。
- README 与实际默认参数保持一致，尤其是 6008 上传代理、1000 步训练和点云下载入口。
